# RP-Hub 私人站点

在你自己的 Cloudflare 账号中部署 RP-Hub。电脑打开私人站点即可登录，Android 本地版可以扫码或填写同一站点地址。首次连接会列出本机与云档，迁入会保留双方的独立进度。

[![部署到我的 Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https%3A%2F%2Fgithub.com%2FHosiyru%2Frp-hub-private)

1. 打开 APK 的「设置 → 私人站点与登录 → 部署到我的 CF」，生成并妥善保存站主认领口令。如果从本仓库按钮开始，可在密码管理器中生成 43 位随机字母数字串作为口令。
2. 在 Cloudflare 官方页面登录，连接自己的代码仓。为新站点选一个独立项目名，核对 D1、私有 R2、Queue 的名称；在 CLAIM_SECRET 中填写刚保存的口令。首次使用 R2 时按 Cloudflare 界面开通服务，账单归所选账号。保留模板的构建和部署命令。
3. 打开部署结果给出的站点地址，填写站主认领口令，生成并保存「本站账号名 + 登录密钥」，完成认领。「检查本站绑定」可验证 D1、R2 与队列。
4. 电脑端生成一次性手机配对码，APK 扫码后确认登录。也可在 APK 输入站点地址及本站凭据。站主可以生成邀请码给其他玩家，每个玩家独立保存。
5. 点击「比较本机与云端」。取消预览不会传输存档。明确迁入后可分别打开两边的历史；中途断网时可继续同一次迁入。日常同步在「继续游玩」单独设置。

6. 手动模式下点「上传本机进度」或「拉取并打开云档」。自动模式在本设备有变化、回到前台和网络恢复时接续。有进度的两台设备第一次连接时，可以分别保留。用「查看云端分支」打开另一条进度。
7. 自动模式可由私人站点接手普通聊天。关屏前看到站点接单后，可以在另一端继续，或在「后台生成」查看进度和中断前的段落。工具续调和辅助模型仍使用设备侧配置。

8. 《命运之刻》战后可以先领物、换装，点 NEXT 后的待发文字也会保存。自动模式等聊天顶部显示「游戏进度已同步」，再换设备。若显示「正文已同步 · 游戏进度待齐」，说明最新回合的游戏快照尚待确认。手动模式先在原设备上传，再到另一台拉取同一分支。私人站点和 APK 都应更新到 0.5.0 或更高版本。

9. 在「设置 → 本地存档 → 图库」查看、下载原图。在聊天里点图片可打开原图。新画风从新图起生效，想改变某张旧图时，点那张图上的重绘按钮。缺图时可在图库选原文件补回。使用旧魔改站点的玩家也可填写原站地址，按历史参数取已保存的图。旧站限制跨域读取时，请从旧图库下载原文件。
10. 图片默认随本机进度保存。启用私人站点后，原图随所选的同步方式进入自己站点的私有 R2。兼容生图服务的密钥在各设备单独填写；查看已同步的图无需生图密钥。

启用自动接续时，如本机已有聊天模型配置，私人站点会为该账号准备后台生成。普通聊天的模型密钥按账号及完整模型地址加密保存。妥善保留部署时的 CLAIM_SECRET，更换后旧密钥需重新配置。自定义模型站点须由站主在 Worker 文本变量 MODEL_ORIGINS 添加对应 HTTPS 来源，多个来源用逗号分开。导出和同步档会过滤已识别的模型密钥字段。

在不同域名之间，浏览器的本地存储各自独立；迁移旧域名上的本地档，可从旧站导出，在新站的「本地存档」先导入。纯本地游玩不需要 CF。

## 从旧魔改站迁入

进入「本地存档 → 换机档案 → 迁入旧魔改分片档」。在 Windows 用页面提供的工具从旧站下载 `.rphsave`，手机或电脑用「选择档案导入」预览。也可在电脑直接选择含 `manifest.json` 和 `chunks/` 的目录。确认后得到独立进度，可以留命名点和换设备续玩。旧插件数据随档保存。原版角色卡工坊、预设仍从原入口使用。

## 找回误删的角色

进入「本地存档 → 单卡恢复」。删除副本保留 30 天，也可先打开换机档案、选命名存档点或点击「查看私人站点备份」。按实例 ID 选定角色后，应用会打开一份合并进度，保留其他卡此刻的聊天、原图和游戏记录。个人云端按分支列出最近 7 个日点和 4 个周点；手动模式的云端副本以最近一次成功上传为准。

## 站主更新

登录原来的私人站点，打开「私人站点与登录 → 站点版本 → 检查新版」。确认目标版本后点「更新本站到 …」。可以关掉页面或电脑，稍后回到同一入口查看。显示「已上线」时，原地址的 Worker 已经返回对应的发行提交。普通玩家继续使用原账号。

首次启用时，在现有 Worker 的 Settings → Builds → Deploy hooks 给生产分支创建一个钩子，把完整网址存入同一 Worker 的加密 Secret `RP_UPDATE_HOOK`。使用本版模板创建的项目把生产部署命令设为 `npm run deploy`。较早的一键部署副本使用下面这条部署命令，使旧私仓也能读取公开发行版。首次从 0.6.1 或更早版本接入，需要先用本版发布工具和已有绑定部署一次入口。部署命令、密钥和钩子均属于站主自己的 Cloudflare 账号。

```sh
git fetch https://github.com/Hosiyru/rp-hub-private.git main && git show FETCH_HEAD:cloud/deploy.mjs > .rph-deploy.mjs && node .rph-deploy.mjs
```

按钮会锁定检查时的公开提交。构建工具核对原数据库内的站点身份，按发行版的锁文件安装依赖、应用迁移并发布到现有 Worker。失败时可查看该 Worker 的 Builds 日志，再回应用检查、重试。需要回退时，在原 Worker 的 Deployments 选择兼容的上一版本；数据库和私有桶沿用原资源。

## 构建

使用 Node.js 22 或更高版本，执行 npm ci、npm run build。私有站点使用 Workers Static Assets、D1、私有 R2 和一个队列。部署脚本按 DB 绑定应用迁移。相同站点再次发布时使用原有绑定，迁移工具记录已应用的版本。已有站点原地更新时请保留 Worker 地址、同一组 D1、R2 和队列绑定、原 CLAIM_SECRET；从现有项目发布新版。APK 覆盖安装同一包名、同一签名的版本即可保留本地档。个人账号或站点认领秘密不写入仓库。
